# 回锋 · 沉钟寺

基于 TypeScript、Canvas 2D 和 Web Audio 的浏览器单人动作游戏原型。
以“掷刃—召回路径”为核心战斗机制，结合种子驱动的箱庭关卡和程序化美术、音效，
在无需后端和外部运行时素材的静态站点中实现可玩的游戏流程。

[在线试玩](https://huifeng.pages.dev/) · [游玩指南](docs/PLAYING.md) · [开发指南](docs/DEVELOPMENT.md)

当前包含 2 章、6 层、Boss 战、死亡重试与通关流程；美术以“青铜 · 朱砂 · 墨”的东方钟寺为主题。
项目已具备自动化检查与性能测量工具，但仍处于原型完善阶段，不代表完成产品级验收。
线上地址是已部署的试玩入口，尚无完整线上通关验收记录，也未核对部署版本与当前提交的一致性。

## 工程实现

| 设计 | 实现与取舍 |
| --- | --- |
| 轻量浏览器运行时 | TypeScript strict + Vite；Canvas 2D 绘制、Web Audio 合成，无运行时包依赖或后端。 |
| 程序化表现 | 角色骨骼、IK、布料与绳索、背景和音效由代码生成；降低外部素材依赖，但绘制成本需要专门控制。 |
| 可复现的地图布局 | 种子驱动房间拼接，同一局死亡重试保留布局；不承诺战斗 AI 和特效的确定性重放。 |
| 有界主循环与画质 | 半固定物理子步、追帧预算、画布像素上限和粒子上限；低画质减少绘制，不改变碰撞和战斗数值。 |
| 静态交付 | 相对资源路径构建，可部署到 Cloudflare Pages 或外部站点子路径。 |

模块按职责组织：`core/` 提供输入、循环、画质和音频基础设施，`world/` 管理生成与碰撞，
`entities/` 管理实体，`render/` 提供程序化模型与绘制，`data/` 存放内容配置，
`game/` 编排状态与关卡。当前 `game/level.ts` 仍同时承担运行时、战斗结算和渲染编排，
尚未实现彻底的模拟／渲染解耦。详细代码地图与内容扩展方式见[开发指南](docs/DEVELOPMENT.md)。

## 快速开始

需要 Node.js 20+（`.nvmrc` 与 CI 使用 20）。在仓库根目录执行：

```bash
npm ci
npm run dev       # http://localhost:5173
```

基础检查与生产构建：

```bash
npm test          # 源码/测试类型检查 + 单元测试
npm run build     # 构建静态产物到 dist/
```

浏览器回归、调试参数与内容扩展见[开发指南](docs/DEVELOPMENT.md)，
发布步骤见[部署指南](docs/DEPLOYMENT.md)。

## 验证范围与局限

| 检查 | 当前范围 |
| --- | --- |
| 单元测试 | 循环时间预算、画质策略、存档和固定种子的地图生成；不覆盖完整战斗与 Boss 行为。 |
| Chromium 回归 | 生产预览上的画布上限、暂停粒子、输入清理、练习局记录等基础设施行为。 |
| CI | 自动执行类型检查、单元测试、构建及生产预览浏览器回归，见 [workflow](.github/workflows/ci.yml)。 |
| 性能测量 | 保留指定环境下的更新/绘制与帧间隔测量，见[性能报告](docs/PERF.md)；不是通用 FPS 保证。 |

尚无完整人工通关、Safari / Firefox 或低端真机的验收证据；自动化通过不等于手感与玩法已验证。
目前仅支持键鼠，不支持触屏；地图可达性检查是近似算法，敌人仇恨也不检查视线。
