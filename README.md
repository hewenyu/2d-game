# 回锋 · 沉钟寺

一款在浏览器里玩的 2D 横版魂系小品。关卡是随机生成的箱庭，一层层往下闯，每 3 层一场守钟人战。

美术方向是「青铜 · 朱砂 · 墨」的东方沉寺：斗笠蓑衣的剑客，头罩铜钟的失声僧，持编钟盾的钟卫，黄符折成的符蛾，背上长着梵钟的守钟人。所有角色都是代码实时绘制的骨骼模型（IK 四肢、布料与绳索物理）。

> 刀是钟舌，丝是归途。掷出它，再唤它回来。

三百年前，始钟裂了，万钟逆鸣，沉钟寺一层层沉进了渊里。一个戴斗笠的人带着一截钟舌铸成的刀走下山门，去找一个声音。世界设定见 [docs/WORLD.md](docs/WORLD.md)。

- 6 层 / 2 章：沉钟寺 · 外墓（第 1–3 层）→ 溺钟渊（第 4–6 层）
- 每一局用新的种子，每层布局都不同；同一局里死亡重来，布局不变
- 预计首次通关 15–30 分钟（视死亡次数而定）
- 序章、章节题词、每层两块可阅读的碑文、Boss 的名号与遗言、通关尾声
- 纯静态网页：没有服务器、没有外部资源，美术与音效全部由代码实时绘制 / 合成

## 操作

| 按键 | 动作 |
| --- | --- |
| A / D（← / →） | 移动 |
| 空格 / Z | 跳跃（按住跳得更高）；S + 空格 从单向平台落下 |
| J / X / 鼠标左键 | 斩击；按住 W 上斩，空中按住 S 下劈（命中敌人或尖刺会弹起） |
| S（↓） | 按住下蹲：可以钻过一格高的缝隙，敌人钻不过去；蹲着冲刺是滑铲 |
| K / Shift / C | 冲刺（全程无敌，空中可用一次） |
| L / V / 鼠标右键 | 掷刃（鼠标瞄准，或用方向键：上 / 斜上 / 空中斜下）；刃离手后再按一次 = 召回 |
| E / Q | 饮灯油，回复 2 点生命（只能在地上，动作慢） |
| W | 在灯龛前点灯 / 休憩（回满、敌人复活、可以花余烬升级）；在碑前阅读碑文 |
| Esc / P | 暂停 |

### 核心机制：回锋

- 刃钉进敌人身上后召回：会把它**撕**出来，造成额外伤害
- 召回途中，刃会**贯穿**路径上的所有敌人，伤害远高于普通斩击。金色虚线是召回路径，会被命中的敌人身上有虚线圈
- 刃钉进侧墙时，会变成一个**落脚点**，可以站上去（只能召回取回，不会被身体碰掉）
- 钟卫的盾挡正面，但挡不住从头顶来的下劈和从背后来的回锋

### 魂系循环

- 死亡后余烬留在倒下之处；再死一次就没了。进入下一层时，留在上一层的余烬也会失去
- 灯龛是存档点：点亮后死亡会在最近点亮的灯龛重生
- 掉进铜戟（尖刺）扣 1 点生命，并回到最近的安全地面
- 死亡画面会写出死因，并给出这种攻击的应对方法

## 本地开发

需要 Node.js 20 或更高（`.nvmrc` 与 CI 使用 20）。

```bash
npm ci
npm run dev        # http://localhost:5173
npm run build      # 类型检查 + 打包到 dist/
npm run preview    # 本地预览 dist/
```

开发时的调试参数（只在 URL 带 `?debug` 时生效，不影响正式玩家）：

- `?debug&level=2`：从第 3 层（第一个 Boss）开始，层数从 0 计
- `?debug&god`：无敌
- `?debug&gallery`：角色图鉴，放大展示每个角色模型的各个状态（←/→ 翻页）
- 这种中途开始的“练习局”不计入最佳记录

### 画质与性能

默认保持全部背景和战斗效果，但将画布的实际渲染像素限制为最多 1920×1080。
窗口仍按原比例铺开，逻辑视口保持 960×540；鼠标坐标、碰撞、攻击判定不随画质改变。

画质参数对正式玩家也有效，不需要 `debug`：

| URL 参数 | 行为 |
| --- | --- |
| `?q=med`（默认） | 最多 1080p 渲染，保留完整装饰效果 |
| `?q=low` | 最多 720p 渲染，减少视差层，关闭光束、尘埃及全屏暗角/色调；保留战斗提示 |
| `?q=high` | 保留完整效果，不限制总像素数（DPR 仍最多 2），适合高性能设备或对比基准 |
| `?q=auto` | 从 high 开始，根据持续的真实帧间隔降档；本次页面会话中不自动升回 |

低配置电脑或关闭硬件加速的浏览器建议先用 `?q=low`。自动降档需要采样时间，不承诺所有设备都达到 60 FPS。
自动模式不能区分渲染瓶颈和浏览器省电限帧；若浏览器主动限制为 30 FPS，可手动选择 `med` 或 `high`，避免不必要的降档。
低档主要减少绘制开销，当前仍创建完整背景缓存，不代表离屏背景内存同步减少。

后台页面不推进游戏或绘制；回到前台重置时钟与输入，不补算离开的时间。
单帧最多 12 个物理子步，每步不超过 1/120 秒；严重卡顿时丢弃超出 0.1 秒的积压时间，避免无限追帧。
出口装饰粒子只在模拟更新中生成，粒子总量最多 512，暂停/阅读/休憩期间不再因反复绘制而增长。

### 验证与基准

```bash
npm test                   # 源码/测试类型检查 + 单元测试
npm run build              # 生产构建
npx playwright install chromium
npm run preview -- --port 5399 --strictPort
```

保持预览服务运行，在另一个终端执行：

```bash
npm run test:browser -- http://localhost:5399/
npm run perf -- --url http://localhost:5399/ --dprs 1,2 --depths 0,2,3,5
npm run perf -- --url http://localhost:5399/ --q low --dprs 2 --depths 0
```

CI 分别执行类型检查、单元测试、构建和基于生产预览的 Chromium 回归。
单元测试覆盖时间预算、画布尺寸/画质策略、存档和固定种子的地图生成；浏览器回归覆盖暂停粒子、画布上限、输入清理与练习局记录等行为。
地图布局的种子可复现不等于整局战斗可重放：敌人行为和部分特效仍使用非种子随机数。

性能脚本分别记录隔离的更新/绘制耗时和实际 rAF 帧间隔；隔离绘制带强制像素读回，不能直接当成玩家实际 FPS。
对比改造前后时，必须使用同一个脚本、浏览器、种子、关卡、窗口尺寸、DPR 与启动参数，且明确画质档位。
默认无头浏览器的结果只代表该测试环境，不能代替低端真机、Safari 或 Firefox 的实测。

## 部署到 Cloudflare

`vite.config.ts` 设置了 `base: './'`，打包结果全部使用相对路径。所以 `dist/` 可以放在任何域名、任何子路径下运行，不需要额外配置。

### 方式 A：Cloudflare Pages 连接 Git 仓库（推荐）

1. 打开 Cloudflare Dashboard → Workers & Pages → Create → Pages → Connect to Git，选择这个仓库
2. 构建设置：
   - Framework preset：`None`（或 `Vite`）
   - Build command：`npm run build`
   - Build output directory：`dist`
   - 如果这个项目在别的仓库的子目录里，把 Root directory 设为该子目录
   - 环境变量 `NODE_VERSION` = `20`（可选；仓库里已经有 `.nvmrc`）
3. 保存并部署。之后每次 push 都会自动重新部署

### 方式 B：命令行直接上传

```bash
npm run build
npx wrangler pages deploy dist --project-name huifeng
```

### 方式 C：挂到已有站点的子路径下

把 `dist/` 里的全部文件复制到外部项目的静态目录，例如 `public/games/huifeng/`，然后随外部项目一起部署。访问地址是 `https://你的域名/games/huifeng/`。

注意：链接要带**结尾的斜杠**。否则相对路径会解析到上一级目录。

### 往后加关卡

在 `src/data/chapters.ts` 里追加配置即可，不用改其他代码：

```ts
// 在某章的 levels 里加一层
{ kind: 'normal', cols: 5, rows: 4, enemies: 16, pool: { pilgrim: 2, moth: 2, guard: 3 }, loot: 4, hpScale: 1.6 },

// 或者追加一整章（biome 用 world/biomes.ts 里已有的，或者新加一套配色）
{ name: '第三章名字', biome: 'abyss', levels: [ ... ] },
```

- `cols × rows`：房间网格大小，决定这层有多大
- `enemies` / `pool`：敌人数量和各种类的比例
- `kind: 'boss'`：这层底部会生成 Boss 竞技场
- 在 `src/data/lore.ts` 的 `LEVEL_NAMES` / `STELES` 里按层数补上层名和碑文（不补也能玩，只是没有碑）

### 加房间模板

在 `src/world/rooms.ts` 的 `ROOMS` 里加一个 30 列 × 17 行的字符画：

| 字符 | 含义 |
| --- | --- |
| `#` | 岩石 |
| `.` | 空气 |
| `=` | 单向平台 |
| `^` | 尖刺 |
| `?` | 50% 概率为岩石 |
| `e` / `g` / `f` | 地面敌人 / 偏向钟卫 / 飞行敌人的出生点 |
| `$` | 遗骸（余烬宝箱） |
| `S` | 灯龛候选位置 |
| `L` | 吊灯 |

障碍的设计原则：挡在通路上的东西都要给玩家选择。悬在地上、底下留一格空隙的石块，可以跳过去，也可以蹲着钻过去；生成器会自动给它挂上铁链。实心的台阶只用来造落差，不要横在唯一的通路上当墙。

出口会由生成器自动挖开：左右在第 11–14 行，上下在第 12–17 列。所以这些位置附近不要放关键结构。生成后会自动校验整层能否走通；走不通会换一个种子重新生成。

### 加新敌人

1. 在 `src/render/models/` 下写它的模型（参考 `monk.ts`），在 `src/game/gallery.ts` 里加几格用来检查
2. 在 `src/entities/enemies/` 下新建一个类，继承 `Enemy`，写 `update`（状态机），`draw` 里把状态交给模型
3. 在 `src/data/chapters.ts` 的 `EnemyKind` 里加上它的名字
4. 在 `src/game/level.ts` 的 `spawnEnemies` 里加上对应的 `new`
5. 在 `src/data/tips.ts` 里加上它的死因提示

## 已知问题

- 只支持键盘 / 键鼠，触屏设备无法游玩
- 关卡“能否走通”的校验是近似的（按跳跃高度和距离估算），极少数情况下可能出现需要精确操作的跳跃
- 敌人的仇恨判定不检查视线，可能隔着墙被发现
